# 9090 배차 업무 기준

- 병원: 더조은요양병원, 휴요양병원, 송라요양병원, 고려대련요양병원, 시티요양병원, 장성요양병원.
- 사장님은 관리자이고 사용자님은 71나9090 기사다. 사용자 요청에 따라 지정된 기존 관리자 계정은 관리자 권한과 기사 역할을 함께 유지한다.
- 관리자가 배차완료 처리한 예약만 9090 차량과 기사에게 배정한다.
- confirmed 표시명은 배차완료, completed 표시명은 이송완료로 구분한다.
- 나머지 차량 연락은 관리자가 개인적으로 처리하며 9090 운행 목록에 포함하지 않는다.
- 접수(created_at) 후 24시간 동안 미배차인 requested/approval_pending 예약만 자동 취소한다. 확정·운행·완료·이미 취소·반려된 기록은 자동 취소하지 않는다.
- 자동 취소는 브라우저가 닫혀 있어도 서버에서 실행한다. 주기 작업의 실행 간격만큼 처리 지연이 생길 수 있음을 명시한다.
- 배차와 자동 취소가 동시에 실행되어도 같은 예약이 양쪽 처리되지 않도록 서버에서 행 잠금과 상태·기한 재검사를 한다.
- 기사에게는 본인에게 배정된 예약만 DB 권한으로 공개한다. 화면 필터만으로 접근을 제한하지 않는다.
- 휴대폰 앱과 푸시 알림은 후속 작업이다. 현재 알림 전달이 구현됐다고 표시하지 않는다.

## 확인한 구조

운영 reservations에 vehicle_id, driver_id UUID 열이 있다. 외래 키 대상, 기사와 profiles 연결, 기존 UPDATE 정책과 트리거는 추가 확인이 필요하다.

## 적용 전 확인

1. dispatch-audit.sql로 컬럼, 제약, 정책, 트리거, 예약 함수와 cron 설치 상태를 확인한다.
2. 71나9090 차량 레코드 및 실제 기사 계정과 연결된 driver 레코드를 확인한다. 임의의 기사 계정을 생성하거나 관리자 계정을 기사로 변경하지 않는다.
3. 기존 정책을 유지할 수 있는 배차 처리 경로를 정한다. 서버는 활성 관리자와 고정 차량/기사 및 24시간 기한을 검증해야 한다.
4. 자동 취소 작업 및 필요한 권한 변경안을 구체적으로 검토한 뒤 적용한다.
5. 가상 예약으로 배차, 기사 조회 제한, 기한 경계, 동시 처리, 재실행을 검증하고 운영 배포한다.
