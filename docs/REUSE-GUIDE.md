## 새 프로젝트를 시작할 때 전달할 문장

> 첨부한 EMS CONNECT 재사용 패키지를 기반으로 새 호출·예약 프로그램을 만들어 주세요. 먼저 README.md와 REUSE-GUIDE.md를 읽고, 현재 EMS CONNECT 운영 프로젝트와 DB에는 접속하거나 변경하지 마세요. 새 저장소·새 Supabase 프로젝트를 사용하세요. 재사용 가능한 기능과 이번 서비스에 맞게 바꿀 항목을 분석한 뒤 진행해 주세요. SQL은 기존 DB에 추가했던 참고 자료이므로 새 DB에서 바로 실행하지 마세요. 기존 9개 테이블의 스키마와 RLS를 먼저 새 서비스에 맞게 설계해야 합니다.

## 재사용 가능한 기능

- 이메일 가입·로그인, 병원 소속 지정과 관리자 승인, 역할별 메뉴.
- 예약 입력·목록·필터, 배차·타차량배차 분리, 기사 운행 목록.
- 이동중 → 이송중 → 완료, 실시간 구독과 재조회 보완.
- 배차 전 수정·취소, 배차 후 관리자 승인, 충돌·중복 승인 차단과 이력.
- Android PWA 설치, Web Push 큐·재시도·기기별 전송 기록.
- 예약별 비공개 사진 1장 업로드·교체, 병원 다운로드, 소속별 접근 차단.
- 병원별 주간 Excel 수동 다운로드, 타차량 금일·월별 누적 조회.

## 구성과 설정

프런트엔드는 React + TypeScript + Vite, 인증·데이터·파일은 Supabase, 배포는 Vercel입니다. `package-lock.json`으로 당시 의존성 버전을 보존합니다.

압축에는 `src`, `public`, 빌드 설정, 패키지 파일, 키가 비어 있는 `.env.example`, 이 가이드와 기능 검증 요약이 있습니다. `reference-sql`은 운영 DB에 적용했던 추가 SQL과 서버 함수의 참고본입니다. 계정 식별자·프로젝트 주소는 예시 표시로 치환했습니다.

**새 DB 전체를 만드는 스키마는 포함돼 있지 않습니다.** 원래 Supabase에 이미 존재하던 hospitals, profiles, vehicles, drivers, reservations, vehicle_locations, dispatch_checks, activity_logs, notifications의 전체 생성 SQL/RLS는 저장소에 없으므로, 새 프로젝트에서는 이를 별도로 설계하거나 승인받은 스키마 전용 내보내기가 필요합니다. 추가 SQL만 실행해서 완성되는 패키지가 아닙니다.

원본의 정확한 코드는 Git 태그 `ems-connect-starter-2026-11-20`으로 보존합니다. 압축은 다른 서비스로 옮기기 위해 운영 연결 정보를 제거한 파생본입니다.

## 처음 실행

1. 운영 EMS CONNECT 폴더와 다른 새 폴더에 압축을 풉니다.
2. Node.js 환경에서 `npm ci`, `npm run dev`를 실행합니다. DB 설정을 비워둔 상태에서는 예약 화면 미리보기로 시작합니다.
3. 실제 기능을 붙일 때만 새 프로젝트의 URL과 공개용 키를 `.env.local`에 입력합니다. 서비스 역할 키·비밀키는 프런트엔드나 Git에 저장하지 않습니다.
4. 새 DB/RLS·계정·차량·푸시·Storage·배포를 구성하고 단계별 검증합니다.

## 반드시 서비스에 맞게 바꿀 것

- EMS CONNECT 상호·아이콘·색상, 병원/고객/기사 용어와 예약 입력 필드.
- 71나9090 단일 차량 가정과 관리자 겸 기사 구조. 다차량은 별도 배정 모델이 필요합니다.
- 소속 격리·계정 승인·상태 전이·24시간 자동 취소·수정 승인 기준.
- 함수 내 지정 기사·차량 식별자, Supabase 프로젝트 참조, 사이트 주소/CORS, 이메일 리다이렉트.
- 새 VAPID 키·서버 비밀·크론 작업. 기존 운영 비밀은 복제하지 않습니다.
- 사진 보존·삭제 기준, 개인정보 처리, 정산 집계일 기준.

## 검증에서 배운 점

- 화면에 버튼이 있다는 것과 DB 저장·권한이 맞다는 것은 별개입니다. 브라우저 → 저장 → 다른 계정 조회까지 확인합니다.
- 요청의 예상 버전과 행 잠금으로 덮어쓰기·중복 승인·상태 단계 건너뛰기를 막습니다. 소속 NULL은 반드시 권한 없음으로 처리합니다.
- 실시간 연결만 믿지 않고 화면 재개/네트워크 복귀/주기적 조회를 보완합니다. 작성 중인 폼은 갱신으로 지우지 않습니다.
- 푸시 서비스의 전송 성공은 휴대폰에서 사용자가 읽었다는 증거가 아닙니다.
- 비공개 Storage + 실제 RLS 테스트가 필요합니다. 버튼 숨김만으로 파일 접근을 통제할 수 없습니다.
- 금일·주간·월간 집계는 한국 시간 경계와 집계 날짜를 명확히 합니다. 서버 조회 제한을 넘는 기록은 페이지를 나눠 가져옵니다.
- 검증은 승인된 가상 기록으로 하고 시험 종료 후 원상 복구합니다.

## 현재 기준본의 한계

예약 생성의 서버 중복 방지, 주간 Excel 서버 자동 보관, 장애 시 백업·복구 절차, 푸시 열람 확인은 완성 기능으로 간주하지 않습니다. 현재 주간 Excel은 수동 저장입니다. 운영 계정/병원별 화면·실제 휴대폰 환경은 새 서비스에서 다시 검증해야 합니다.

이 패키지는 설계·화면·구현 시간을 줄이는 출발점입니다. 새 서비스의 DB·권한·배포·검증까지 생략할 수 있다는 의미는 아닙니다.
